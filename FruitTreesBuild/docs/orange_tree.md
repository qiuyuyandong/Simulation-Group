# 橙子树形态与叶片放置

本版仅调整 Sapling 橙子路径。苹果 Space Tree 的形状配置与随机放置顺序保持原样。
日常入口仍是根目录三个固定脚本，没有新增制作入口。

## 默认设计

| 配置 | 默认值 | 含义 |
|---|---|---|
| treeHeight | 3.2 | 枝干高度目标，米；叶片可能略高 |
| trunkHeight | 0.5 | 新增裸干段长度，米；最低实际叶片不必恰好等于该值 |
| crownWidth | 3.2 | 枝干中心线 X/Y 最大宽度目标，米；保持不对称性 |
| trunkDiameter | 0.13 | 根部枝干直径目标，米 |
| leafCount | 1600 | 叶片对象数，包括其内建叶柄，不另算叶柄对象 |
| leafLength | 0.105 | 叶片原型连同短叶柄的长度目标，米；单片缩放 0.8–1.15 |
| fruitCount | 80 | 果实数，ID 保持 Fruit_0001 等映射 |
| leafFruitClearance | 0.006 | 实际果实保守包络之外的叶片间隙，米；允许 0–0.05 |

树形采用较低分叉、三条主干方向及固定三级枝条的设计近似，继续使用原 Sapling 核心。
这不是某个果园、品种、砧木或树龄的实测重建。实景图只提供局部形态参考，不能给出绝对尺寸。

## 连接和避让

1. 根据原中心线及半径扫掠八边管状外观枝干，保留细枝和枝间空隙。
2. 叶片不再使用含大片透明区域的矩形卡片，而按原贴图 alpha 轮廓采样成有轻微弯曲的薄网格；不更改原 PNG。
3. 每片叶片在同一网格内带短三维叶柄，使用实际叶柄基部顶点定位到实际枝干表面；方向依据所依附的枝条。
4. 先放置果实，根据每个实际果实的变换后顶点拟合保守包围球，包括果梗。不是使用目标直径代替实际尺寸。
5. 逐个放置叶片，检查全部叶片三角面与“果实包围球 + 间隙”的距离；冲突时重新选择枝条点、朝向和缩放。
6. 叶柄基部至少相隔 leafLength × 0.33，抑制局部堆叠；这不等于所有叶片表面互不相交。
7. 生成时实算叶柄接触和叶果避让，记录被拒绝的候选数；达到容量限制时报错，不暗中少生成叶片。

这些包围球仅用于生成过程中的保守外观避让，不保存为碰撞对象，不新增 collision 元数据。
新叶片仍使用 leaf 角色、原果实仍使用 fruit 角色；叶柄不另增角色、对象数量或逐叶素材级标注。

## 检查范围

构建记录 metadata.json 保存当次检查结果。人工调整后这些是历史记录，不能当成当前模型已重新检查。
素材级 asset_metadata.json 仍在人工保存 asset.blend 后通过 generate_metadata.py 独立提取，规范版本不变。
内部 tests/citrus_blender_checks.py 可在 Blender 后台加载已保存模型后检查当前几何；这是测试文件，不是第四个日常入口。

不承诺所有叶片/叶片或叶片/木质部位都无穿模，也不承诺所有果实都对任意视角可见。
保守包围球可能比果实局部真实表面大，因而可能额外稀疏一些叶片。枝干交界为视觉嵌合，不是水密实体布尔并集。
没有更改成熟度贴图、加入生育阶段、碰撞系统、叶片合并或整园搭建。

## 形态参考来源

- [NC State Extension：Sweet orange](https://plants.ces.ncsu.edu/plants/citrus-x-sinensis/)：圆形树冠倾向、互生叶与叶形等定性参考；默认尺寸不是该页面给出的特定果园参数。
- [UF/IFAS：Mechanical Pruning of Citrus Trees](https://ask.ifas.ufl.edu/publication/HS1267)：树形受品种、砧木、树龄、环境及修剪制度影响，不能把单张照片的形态当作所有柑橘统一标准。

原叶片图片和果实模型的授权状态仍须单独核查，没有通过此次几何修改改变原素材许可。
